# Working in NASA-2026

Start from a GitHub issue. Use one branch and worktree per task. Include reproducible checks in the pull request and leave merging to the team integrator.

Track NASA source provenance, checksums, units, reference frames and limitations in the corresponding issue and source record. Keep credentials, local environments and raw downloads untracked. Use synthetic data only in explicitly labelled tests. Report missing or unverified data explicitly.

## Web app (`web/`)

The SITE REGRET web app lives in `web/` (Next.js static export, TypeScript strict). Read `docs/TRABAJO_REALIZADO.md` first, then `web/ARCHITECTURE.md` and `web/DECISIONS.md`.

- Setup: `cd web && npm ci`. Run the app with `npm run dev`; the static build with `npm run build && npm run serve`.
- Before opening a pull request run `npm run verify` (typecheck, lint, 63 Vitest tests, build, 47 Playwright E2E tests including the axe-core WCAG A/AA audit). If the browser tests cannot run on your machine, run at least `npm run typecheck && npm run lint && npm test` and say so in the PR.
- Never edit `web/data/source/`: those files are the original transfer package and are checked against `SHA256_TRANSFERENCIA.txt`. `web/public/data/` is generated by `npm run data`.
- Scientific rules (covered by tests, do not break): only sites A/B (ROI 4 and 6), windows W1/W2 and heights 0/2/10 m; variant counts are not probabilities and team hypotheses stay separate from published clones; no Monte Carlo, energy, radio-link, temperature, radiation, landing-safety or structural models and no 0–100 scores; never interpolate categorical states or treat `UNKNOWN`/`null` as shadow; never combine nominal ephemerides with variant horizons; the criterion is chosen before the winner is shown; colours A orange, B cyan, uncertainty violet.
- UI text is bilingual: write new strings as `L("español", "English")` (see `web/src/lib/i18n.ts`). The engine sentence `summary_es` is shown verbatim.
